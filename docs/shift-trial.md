# ONOGAMI シフト希望収集・操作テスト v0.1

2026-09-13。承認済みの希望提出方針を、架空店舗・スタッフの操作テストとして実装。

## 目的と範囲

希望の収集・連絡を省力化し、店側の人数、本人の希望、教育目的の増員などの判断材料をまとめる。管理者の配置判断は残す。今回は説明なしに希望提出を行えるかを試す版。

- `/shift/trial` でスタッフ・管理者・通知を切り替える。
- 月単位は2026年10月、週単位は10月5〜11日の独立したサンプル募集。
- 普段の曜日・時間と働きたい日数を登録し、今回だけの差分を入力する。
- 毎回予定が変わるスタッフにも対応。未登録の日を勤務可能と推測しない。
- 「入れない」「できれば休み」「入れる」「入りたい」を区別する。
- 下書きは提出済みの内容へ自動反映しない。再提出で版を更新する。
- 管理者の代理入力は代理として記録し、本人向けの確認通知を模擬作成する。
- 催促は未提出の人に1募集期間につき1回。テスト操作で時刻到来を再現する。
- 提出された時間を管理者が明示的に配置する。休み希望への配置は本人相談済みの確認を挟む。
- 人数の目安は日全体の人数。時間帯別の充足や担当業務を保証しない。目安超過で公開を止めない。
- 締切後の公開を再現し、公開後は変更依頼→管理者承認/見送り→本人通知を試せる。
- 公開前に希望の時間・種別が変わっている配置は、再確認するまで公開を止める。
- 既存画面を変更せず、専用のテストURLから開ける。

## 表示改善（2026-09-13）

- スタッフ・募集単位・画面の切り替えで外枠が伸縮しないよう、全画面の共通コンテナーを幅100%・上限900pxに統一。スクロールバーの有無による横位置の変化も抑える。
- 通知は「種類と本文が同じ内容」をまとめ、初期表示を短い一覧に変更。行を開くと全文と宛先別の画面リンクを表示する。同じ宛先への複数件は通知件数として保持する。
- 名前はプルダウンで「全員」・各スタッフ・管理者を選択する。通知の種類と組み合わせて絞り込める。本文検索は行わない。該当なし表示と絞り込み解除を用意する。
- 1ページ10種類の内容を表示。月と週を切り替えると通知の絞り込み条件・ページを初期化する。
- 通知画面の確認手順：提出案内4件が1行・4宛先にまとまること、行の開閉、名前の選択で1宛先になること、通知のない宛先を選んだときの表示と解除、催促の種類との組み合わせ、宛先からスタッフ画面へ移れることを確認する。

## テスト版の境界

**画面の操作試作。実運用・実店舗の限定試験ではない。**

- 固定の架空店舗・4名の架空スタッフのみ。実店舗・個人情報を読み込まない。
- データはReactのメモリ内。タブを閉じる/再読込で消去。端末間の共有なし。
- LINE認証、LINE/メール実送信、DB保存、Cronは接続しない。
- 本画面の役割切替はテスト操作であり、実際の権限制御ではない。
- スタッフの未提出下書きと管理者の代理入力バッファを分離する。代理入力は提出済み内容（なければ初期条件）から開始し、本人の未提出下書きを読まない・上書きしない。
- 欠員募集・応募の一斉収集、PDF、自動最適化、人件費予測は今回の対象外。
- 既存の打刻・勤怠・給与・店舗設定・認証・DB・通知処理は変更しない。

## 操作の確認手順

1. 田中はるかで10月5日を「入れない」に変更。管理者には提出前の変更が出ないことを確認し、スタッフに戻って提出する。
2. 管理者の日別確認で、5日は配置不可、7日は17〜22時で配置可能になることを確認する。
3. 鈴木まいを選び、勤務可能日を入力する。その他の日が未登録として扱われることを確認する。
4. 管理者から山本直子の希望を代理入力して提出。本人向け通知を確認する。
5. 「時間を進めて試す」の催促を2回押す。未提出者向け通知が重複しないことを確認する。
6. 7日へ田中はるかを配置し、締切後へ進めて公開。スタッフの出勤予定と通知を確認する。
7. 公開後に7日の「入れない」を変更依頼。管理者が承認するまで出勤予定が維持され、承認後に外れることを確認する。
8. 週単位へ切り替え、月の入力と混ざらないことを確認する。

## 検証
